How an agent spends your money, and why it can't overspend

You grant an allowance from your phone. Your smart wallet enforces it on Arc. The agent pays per step in a maze, earns a score it can't write itself, and Chainlink CRE replays the run to check that score.

The run, in order

  1. 0
    Create a wallet

    Face ID makes a passkey, and Circle's relying party registers it. The smart account's address exists at once and deploys on its first operation.

  2. 1
    Pair

    The connector makes its own key and shows a QR code: its address plus a one-time pairing code. The phone scans it.

  3. 2
    Grant

    The phone signs one operation that adds the agent's key to the plugin, with a limit, an end date, an allowlist and the pairing tag. Circle submits it and pays the gas.

  4. 3
    Identity

    On its first check, the agent registers an ERC-8004 identity from the person's wallet, which owns it, and links its own key as the identity's agent wallet.

  5. 4
    Top up

    Before each purchase the agent's key moves just enough USDC into its own Gateway escrow. The plugin counts it against the limit. Gateway only accepts payers with a plain key, so the wallet can't pay directly.

  6. 5
    Pay

    The maze answers 402 with a price. The agent signs the payment with its key and retries. The map plus twelve moves on run 25b9f044 came to 13 payments and $0.022.

  7. 6
    Settle

    The maze verifies and settles through Gateway. Circle batches the transfers onto Arc about every fifteen minutes.

  8. 7
    Reward

    On a solve, the maze checks the identity's agent wallet is the payer, stores the run and its digest, writes the score to the Reputation registry and mints a badge to the identity's owner. Today it signs these with its own key.

  9. 8
    Replay simulated

    The CRE workflow reads the run record inside an enclave and replays every move. It got the same score and digest the maze wrote on chain.

  10. 9
    Deliver the verdict not deployed

    The signed report would go through Chainlink's forwarder to MazeVerdict, which writes the feedback. Then no private key would be behind the score.

  11. R
    Revoke, any time

    The phone signs one operation that removes the agent's key. Its next operation is refused. Money already in its Gateway escrow stays there.

Why the verdict runs on Chainlink CRE

The maze computes the score and signs it. The registry only refuses self-feedback, so nothing stops a seller from flattering its own customers. The fix uses two separate CRE properties for two separate jobs.

Consensus: we can't fake the verdict

A network that didn't play the run re-derives the score from the public record and signs it together.

Enclave: we can't leak the token

The token that reads run records can also rewrite them. The Vault DON releases it only into an attested enclave.

Where it stands

  • Simulated with the CRE CLI on runs 25b9f044 and 83031b89. The simulator states it is not a real enclave.
  • Matched on chain by hand: the workflow does not read Arc yet.
  • MazeVerdict is written and tested, not deployed. Deploying waits on Confidential Workflows beta access.
  • Trusts the record for the payer and the identity. The maze checks these; the workflow does not yet.
  • Revoke stops the agent's key, not money already in its escrow.
